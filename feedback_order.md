## Что нужно исправить / доработать

### 1. Метрики считаются не для того класса

В `train.py` используется:

```python
precision_recall_fscore_support(labels, preds, average="binary")
```

При `order=0`, `not_order=1` sklearn по умолчанию считает метрики для **класса 1 (`not_order`)**, а не для `order`.

**Что сделать:**

- добавить `pos_label=0` (или `pos_label=config.LABEL_MAPPING["order"]`);
- выводить `classification_report` и confusion matrix по обоим классам;
- в README описывать метрики явно: «recall для order», «precision для order».

## На что обратить внимание

В ТЗ был опциональный пункт про **калибровку порога**: пропустить заказ — плохо, лишнее сообщение в таблице — терпимо. Можно чисто ради интереса  и проверки работы модели при разных порогах их подогнать.

Сейчас класс выбирается через `argmax` (порог 0.5). Для такой задачи полезно:

1. На val получить `P(order)` для каждого примера.
2. Перебрать пороги (например, 0.1–0.9).
3. Сохранить лучший порог в `config.py` и использовать в `predict.py` вместо голого `argmax`.

### Лучший чекпоинт

Сейчас модель учится, например, **5 эпох**. После каждой эпохи она проверяется на val — и в конце **сохраняется только последняя**, 5-я.

Проблема: **лучший результат может быть на 3-й эпохе**, а на 5-й модель уже чуть «переучилась» и стала хуже. Но в прод уходит именно 5-я.

### Воспроизводимость

`SEED` в Trainer — хорошо. Для полной воспроизводимости добавь в начало обучения, тк каждый раз при запуске переобучения есть вероятность получать разные результаты:

```python
from transformers import set_seed
set_seed(config.SEED)
```
