# Тестовое задание: ML-классификатор текстовых сообщений

**Формат сдачи:** ссылка на GitHub-репозиторий

Изучая проекты на гите, пришла идея тестового задания: необходимо реализовать **ML-пайплайн бинарной классификации** текстов: модель должна по содержимому сообщения определять, является ли оно заказом (`order`) или нет (`not_order`).

> **Важно:** решение должно включать **обучение модели** на предоставленных данных. Использование только внешних API в качестве классификатора **не считается)**.

## Предоставляемые материалы

В папке будет лежать `dataset/` со следующей структурой (в целом полезно будет изучить по каким принципам, соотношениям выстраивается датасет):

```
dataset/
├── train.csv          # обучающая выборка (800 записей)
├── val.csv            # валидационная выборка (200 записей)
├── test.csv           # тестовая выборка (200 записей, без меток label)
└── README_dataset.md  # описание полей и классов
```

### Формат CSV


| Поле    | Тип | Описание                                                         |
| ------- | --- | ---------------------------------------------------------------- |
| `id`    | int | Уникальный идентификатор сообщения                               |
| `text`  | str | Текст сообщения (может содержать переносы строк)                 |
| `label` | str | Метка класса: `order` или `not_order` (отсутствует в `test.csv`) |


### Примеры

**Класс `order`:**

```
заказ 1042
Иван Петров
iPhone 15 Pro - 2
Samsung Galaxy S24 - 1
```

**Класс `not_order`:**

```
Ребят, кто знает, когда будет поставка?
```

## Цель задания

Разработать ML-пайплайн, который:

1. обучает модель бинарной классификации на `train.csv`;
2. оценивает качество на `val.csv`;
3. генерирует предсказания для `test.csv`;
4. предоставляет скрипт inference для новых сообщений;

## Требования к решению

### 1.  Модели (на выбор, тк тебе в целом подойдет любая НЛП-модель)

Допускается использование одной из следующих моделей (или любых других на свое усмотрение). Можно не дообучать готовую, а сделать с нуля свою, на рещультат оценки тествого задания это не влияет:

- `cointegrated/rubert-tiny2`
- `DeepPavlov/rubert-base-cased`
- `distilbert-base-multilingual-cased`

> Дообучение обязательно независимо от выбранной модели.

### 2. Технический стек

- **Язык:** Python 3.10+
- **Запрещено** использовать LLM API (OpenAI, Anthropic, GigaChat и т.д.) как основной классификатор
- **Разрешено** использовать HuggingFace Transformers, scikit-learn, PyTorch, pandas и тд
- Обучение должно быть **воспроизводимым**: зафиксируй `random_seed` (например, `42` главное потом в документации напиши сколько поставил) во всех скриптах
- Не изменяй разметку и состав `train.csv` / `val.csv`

### 3. Опционально (но не обязательно)

- Анализ ошибок: 5–10 примеров, где модель ошиблась, с комментарием почему
- Калибровка порога классификации под наш процесс. Что я имею ввиду:  
  Модель обычно выдаёт не только класс (`order` / `not_order`), но и вероятность (например, 0.73).
  По умолчанию порог часто 0.5: если probability >= 0.5 - `order`.
  Калибровка порога — это подбор другого порога на валидацию, чтобы модель лучше подходила под задачу.
  Пример:
  - Пропустить заказ — плохо, теряются деньги.
  - Лишнее сообщение в таблицу — не критично, менеджер поправит.
  Тогда можно понизить порог, чтобы модель чаще помечала `order` → растёт Recall (меньше пропусков), но больше ложных срабатываний.
- Weights & Biases / MLflow для логирования экспериментов (но можно просто в ридМи файле указать какие параметры были при обучении, как росли метрики и т.д.)

## Формат файла предсказаний


| Поле          | Тип   | Описание                                      |
| ------------- | ----- | --------------------------------------------- |
| `id`          | int   | ID из `test.csv`                              |
| `label`       | str   | Предсказанный класс: `order` или `not_order`  |
| `probability` | float | Уверенность модели в классе `order` (0.0–1.0) |


Пример:

```csv
id,label,probability
1001,order,0.9231
1002,not_order,0.1142
1003,order,0.8744
```

## Inference-скрипт

Скрипт `predict.py` (название любое) должен поддерживать
Как оформишь парметры в запуске неважно, это только пример:
```bash
# Предсказание для одного текста
python -m src.inference.predict --text "заказ 1042\nИван Петров\niPhone 15 Pro - 2"

# Предсказание для CSV-файла
python -m src.inference.predict --input data/test.csv --output submissions/test_predictions.csv
```

**Ожидаемый вывод (пример для одного текста):**

```
label: order
probability: 0.9231
```
